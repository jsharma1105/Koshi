## LinkedIn — long-form post

> **Shipping Koshi v0.8.1 — and finally telling the v0.8.0 story.**
>
> Koshi is an open-source Model Context Protocol (MCP) server that gives
> any agent — Claude Code, GitHub Copilot CLI, Cursor, Windsurf — four
> capabilities that usually take four separate tools: BM25 retrieval over
> your codebase, token-budget-aware context packing, typed persistent
> memory, and per-team quality telemetry. 24 tools. Single binary. 100%
> offline. MIT.
>
> Today's v0.8.1 is small. But the v0.8.0 release a few days ago shipped
> something I want to spend a minute on because it changed how I work with
> agents day-to-day.
>
> **The problem v0.8.0 solved**
>
> The *reasoning* behind a fix almost never leaves the original PR
> description. We pick framework A over B, deprecate column X, accept a
> small perf regression to land a security fix — and that decision lives in
> a Slack thread or a PR comment that the agent will never re-read three
> months later when it has to make the same call again.
>
> So in v0.8.0 we added `koshi_capture_turn`. The agent, at the end of a
> meaningful turn, passes a 1-3 paragraph summary of what it just did (plus
> optional `linked_pr` and `linked_commits`). Koshi runs a deterministic
> pattern-based extractor (no LLM, no round-trip, AOT-compiled, ~ms) that
> pulls out decision-shape sentences — "we chose X over Y because Z", "fixed
> by patching Z", "decided to ship behind a feature flag" — and persists
> each one as a typed `Decision` memory with PR/commit provenance.
>
> No round-trip to OpenAI/Anthropic. No tokens spent. The decision lives in
> a Markdown file in your vault (or a JSON store if you prefer), so Git
> distributes it to the rest of your team automatically. The next time the
> agent asks "have we made a call on X?", it actually finds the answer.
>
> Pair it with a 6-line snippet in your repo's `.github/copilot-instructions.md`
> and Copilot calls `capture_turn` on its own at the end of every turn.
> ([docs/copilot-instructions-snippet.md](https://github.com/jsharma1105/Koshi/blob/main/docs/copilot-instructions-snippet.md))
>
> **What v0.8.1 actually fixes**
>
> v0.8.1 is a maintenance release driven by a bug we caught while
> dogfooding the Copilot CLI personas. Each of the five `koshi-*`
> sub-agents had a frontmatter `tools:` field that listed three built-in
> aliases — `[search, read, agent]` — but no Koshi MCP tools. Per GitHub's
> custom-agent reference, a specific `tools` list enables *only* the named
> tools and silently drops everything else. So every sub-agent started with
> **zero** Koshi tools and had to lazily discover them via tool-search
> before doing any work. Symptom: "the agent said it would use Koshi but
> just sat there." Cause: silent allow-list filter. Fix: 7-file edit sweep
> + a sync version bump across `Koshi.Mcp`, `Koshi.Agents`, the Python
> wheel, and both plugin manifests.
>
> If you use the Copilot CLI personas, `dotnet tool update --global
> Koshi.Agents` + `koshi-agents install --client copilot` and you're done.
>
> **Try it**
>
> - Python: `pip install koshi`
> - .NET / MCP server: `dotnet tool install --global Koshi.Mcp`
> - AOT binaries for 5 platforms (linux-x64/arm64, macOS arm64,
>   Windows x64/arm64): <https://github.com/jsharma1105/Koshi/releases/tag/v0.8.1>
>
> Repo: <https://github.com/jsharma1105/Koshi>
>

## GitHub Release v0.8.1 — narrative body

> *Used by the maintainer to overwrite the auto-generated PR list in the
> v0.8.1 release notes via `gh release edit v0.8.1 --notes-file …`. Same
> content can also be cross-posted to PR #58 (this announcement PR) when
> it lands.*

> ## TL;DR
>
> Maintenance release. If you use the **Copilot CLI sub-agent personas**
> (`koshi-librarian`, `koshi-memory-keeper`, `koshi-context-packer`,
> `koshi-quality-coach`, `koshi-orchestrator`), upgrading is a free toolset
> fix — the personas now load all 24 Koshi MCP tools at startup instead of
> having to lazily discover them through tool-search. Everything else is
> byte-for-byte identical to v0.8.0.
>
> ```bash
> # Python
> pip install --upgrade koshi
>
> # .NET MCP server
> dotnet tool update --global Koshi.Mcp
> dotnet tool update --global Koshi.Agents
> koshi-agents install --client copilot   # or --client both
> ```
>
> ## The bug
>
> All five `.github/copilot/agents/*.agent.md` personas declared
> `tools: [search, read, agent]`. Per the [GitHub custom-agents reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration),
> a specific `tools` list enables **only** the named tools; everything
> else is silently dropped. MCP tools need `<server>/<tool>` namespacing
> (e.g. `koshi/koshi_search`) to be allowed, so each sub-agent started
> with **zero** Koshi tools and had to discover them via tool-search
> before doing any work. The Claude Code personas (`.claude/agents/*.md`)
> were unaffected — they already used explicit `mcp__koshi__koshi_*`
> allow-lists.
>
> ## The fix
>
> Every `tools:` list is now spelled out explicitly:
>
> - `koshi-librarian` — 7 tools (5 retrieval + 2 diagnostics)
> - `koshi-memory-keeper` — 10 tools (all 9 memory + health)
> - `koshi-context-packer` — 6 tools (3 owned + 2 read-only retrieval/memory + health)
> - `koshi-quality-coach` — 6 tools (5 team + health)
> - `koshi-orchestrator` — all 24
>
> Built-in aliases (`search`, `read`, `edit`, `agent`) are dropped entirely
> for parity with the Claude personas — this preserves strict pillar
> isolation (the librarian can't grep arbitrary files, the memory-keeper
> can't read the filesystem).
>
> ## Scope drift caught during the fix
>
> The rubber-duck pass surfaced a second issue: the memory pillar README
> documents **9 tools**, but the `koshi-memory-keeper` persona allow-listed
> only 5. The four v0.8.0 additions — `koshi_capture_turn`,
> `koshi_memory_export_to_vault`, `koshi_memory_import_from_vault`,
> `koshi_memory_sync_vault` — were missing. Both the Claude and Copilot
> variants now include all nine. The `koshi-orchestrator` persona is
> bumped from 20 → all **24** Koshi tools, with the body text refreshed
> accordingly.
>
> ## Release scope
>
> - **`Koshi.Agents` 0.8.1** — carries the persona fix. The seven
>   `.agent.md` / `.md` files are embedded as `<EmbeddedResource>` in the
>   package, so a `dotnet tool update --global Koshi.Agents` plus
>   `koshi-agents install --client copilot` is enough.
> - **`Koshi.Mcp` 0.8.1** — bit-for-bit functionally identical to v0.8.0.
>   The version is bumped in sync to honor the unified-version release
>   convention used by `.github/workflows/release.yml`.
> - **Python `koshi` 0.8.1** — same wrapper, republished so the
>   auto-download flow lines up with the 0.8.1 AOT binary hash baseline.
> - **Native AOT binaries** — rebuilt at 0.8.1 for `linux-x64`,
>   `linux-arm64`, `osx-arm64`, `win-x64`, `win-arm64`.
>
> ## A re-introduction to v0.8.0 — `koshi_capture_turn`
>
> v0.8.1 piggybacks on the v0.8.0 announcement because the headline
> feature there is worth a closer look. The agent passes a 1-3 paragraph
> summary at turn-end (plus optional `linked_pr` / `linked_commits`).
> Koshi runs a deterministic pattern-based extractor — no LLM, AOT-compiled,
> sub-millisecond — that pulls decision-shape sentences ("we chose X over
> Y because Z", "fixed by patching Z", "decided to ship behind a feature
> flag") and persists each one as a typed `Decision` memory with full
> provenance. No round-trip. The decisions live in a Markdown file (or
> JSON, your call) so Git distributes them across the team.
>
> Pair with [`docs/copilot-instructions-snippet.md`](https://github.com/jsharma1105/Koshi/blob/main/docs/copilot-instructions-snippet.md)
> so the agent calls `capture_turn` on its own at the end of every meaningful
> turn.
